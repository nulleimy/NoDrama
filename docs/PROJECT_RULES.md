# NoDrama — Project Rules

## Workflow

The project follows a local-first workflow:

1. Build locally.
2. Verify locally.
3. Commit.
4. Push.

## Branching

- main must stay stable.
- Feature work should use feature/* branches after the initial bootstrap.
- Commit messages should follow Conventional Commit style.

## Technical Rules

- TypeScript-first.
- No secrets committed.
- Environment variables must be documented in .env.example.
- API routes must validate input.
- AI calls must be rate-limited before public release.
- No unlimited AI usage plans.
- All paid plans must use credit/fair-use limits.

## Product Rules

NoDrama is not a fraud or manipulation tool.

Allowed:
- polite refusal
- boundary setting
- apology drafting
- rescheduling
- low-drama communication

Not allowed:
- fake legal, medical, police or emergency claims
- document forgery
- fraud
- scams
- harassment
- coercive manipulation
